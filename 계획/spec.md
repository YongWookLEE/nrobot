# spec — 앤로보틱스 웹 견적서 (임시 시연판)

## 1. 목표와 배경

(주)앤로보틱스의 견적서 프로그램을 **Next.js + TypeScript** 웹앱으로 새로 만든다. 위치는 `C:\danusys\nrobot\nrobot-web`이다.
Vercel 무료(Hobby) 요금제로 올리는 **시험·시연용 임시 배포본**이다.

- 지금은 사용자 본인이 직접 만들고 배포한다. 나중에 회사 사람이 넘겨받아 배포·관리한다.
- **이 폴더(`nrobot-web`)만이 앞으로의 유일한 원본 소스다.** git 저장소도 이 폴더 기준이다(원격: 비공개 `YongWookLEE/nrobot`).
- 개발과 빌드, 배포는 이 폴더 밖의 파일을 참조하지 않는다.

기존 프로그램은 참고 자료로만 쓴다.
- 기존 위치: `C:\danusys\nrobot\nrobot_full`. `quote_app`은 PC용 EXE, `web_quote`는 Flask 웹 1.0이다.
- 새로 만드는 이유는 코드를 깔끔하게 정리하고 사용 기술을 명확히 하기 위해서다.
- **기존 계산식과 규칙은 모두 유지한다.**
- 결과 PDF·Excel은 기존과 **거의 똑같이** 만든다. 금액은 1원도 달라서는 안 되고, 배치와 페이지 나눔도 같아야 한다.

## 2. 범위

**포함**
- 5종 견적서: ① 부가세 표시, ② 부가세 미포함, ③ 비용 분리, ④ 영업1팀 제품, ⑤ 영업2팀 제품.
  - 입력, 계산, PDF·Excel 생성과 다운로드.
- 가격표에서 품목 선택: ①②③은 출입통제 기준가격표, ④⑤는 영업팀 제품가격표를 쓴다.
- 공용 비밀번호 입장 화면.
- 담당자 설정. 견적번호는 브라우저별로 발급한다.
- 입력내용은 브라우저에 자동 저장한다.
- 배포 준비 일체와 인수인계용 안내 문서.

**제외** (이번 시연판에 만들지 않음. 향후 범위는 handoff의 프로젝트 기반 4절)
- 개인 계정 로그인과 관리자 화면(가격표 업로드 포함).
- 서버의 초안·결과 파일 보관, 견적 이력 조회.
- 사전원가표.
- 서버 데이터베이스.
- 실제 Vercel 업로드. 업로드는 사용자가 직접 한다.

- **비교용 기존 견적서**: 실제 연락처가 들어 있으므로 `nrobot-web/private/reference/`에 둔다.
- 가격표를 변환해 만든 데이터와 사진(빌드 산출물).
- 실제 가격표에서 뽑은 기준 데이터. `private/` 아래에 둔다.

**저장소에 올리는 것**
- 소스, 가짜 데이터로 만든 기준 데이터, 합성 시험용 엑셀.

**지켜야 할 규칙**
- 소스·기준 데이터·문서 어디에도 실제 담당자 휴대폰 번호와 실제 가격표 단가를 쓰지 않는다.
- 기존 코드에는 휴대폰 기본값이 박혀 있지만 옮겨 오지 않는다.

`private/`의 파일 배치(고정 이름):
```
private/
├── prices/access.xlsx      ← 출입통제 기준가격표 (원본: 260730_출입통제 기준가격_06.xlsx)
├── prices/catalog.xlsx     ← 영업팀 제품가격표 (원본: (주)앤로보틱스_ 2026년도 견적서 양식.xlsx)
```

단, 단위 검사(`npm test`)는 합성 시험 엑셀로 돌아가므로 `private/` 없이도 통과해야 한다. 실제 가격표를 쓰는 검사는 파일이 있을 때만 돈다.

## 5. 입장 비밀번호 (확정)

- 개인 계정은 없다. 환경 변수 `APP_PASSWORD`에 비밀번호 하나를 정해 두고, 맞게 입력한 사람만 들어간다.
- **보호 범위**: 입장 화면과 그 화면에 필요한 정적 파일을 뺀 모든 페이지와 모든 API다. 가격표 데이터, 제품 사진, 담당자 정보, 견적 생성이 모두 포함된다.
  - 입장하지 않은 페이지 요청은 입장 화면으로 보낸다.
  - 입장하지 않은 API 요청은 401과 `{error}`를 돌려준다.
- 입장 성공 시 서명된 쿠키를 발급한다. 쿠키 속성은 HttpOnly, SameSite=Lax이고, 배포 환경에서는 Secure를 붙인다.
- 쿠키 서명에는 `APP_PASSWORD`가 들어간다. 그래서 **비밀번호를 바꾸면 기존 입장 상태가 모두 무효가 된다**.
- 쿠키 유효기간은 30일이다(조정 가능).
- 화면 위쪽에 '나가기'(쿠키 삭제) 버튼을 둔다.
- `APP_PASSWORD`가 비어 있거나 설정되지 않았으면 **아무도 들어갈 수 없다**. 입장 화면에 "관리자가 비밀번호를 설정하지 않았습니다"라고 표시한다.
- 비밀번호가 틀리면 "비밀번호를 확인하세요"라고 표시한다.
  - 연속 시도를 늦추기 위해 실패 응답마다 약 1초 지연한다(조정 가능).
  - 계정 잠금은 없다.

## 6. 담당자 (확정)

- 담당자 명단은 환경 변수 `STAFF_CONFIG`(JSON 배열)로 받는다.
  - 항목 형식: `{ "id": "string", "name": "이름", "title": "직급", "phone": "010-…", "start": 1 }`
  - 기존 3명의 시작 번호(001/010/020)와 순서는 실제 값으로 사용자가 넣는다. 저장소의 예시는 가짜 이름과 번호를 쓴다.
- 검증 규칙
  - 이름 1~30자, 직급 20자 이하, 휴대폰 30자 이하.
  - `start`는 1~999 정수, `id`는 중복 불가.
  - 최소 1명.
  - 형식이 틀리면 서버가 시작하지 않는다. 화면에는 "담당자 설정(STAFF_CONFIG)을 확인하세요"라고 표시한다.
- 표시 이름은 `이름 + ' ' + 직급`이다(직급이 비면 이름만). 예: "홍길동 대리".
- 화면 작성자 선택지에는 `이름 · NNN부터`를 표시한다.
- 화면에서 담당자 휴대폰을 고치면 그 값을 **그 브라우저에만** 담당자별로 기억한다. 이후 그 브라우저에서는 고친 값이 기본값보다 우선한다.
- 기본값(환경 변수)이 바뀌어도 브라우저에 고친 값이 있으면 고친 값을 쓴다.
- 견적서에 찍히는 담당자 휴대폰은 견적 생성 요청에 담긴 값(화면의 현재 값)이다.

## 7. 견적 계산 (기존 규칙 그대로 — 변경 금지)

모든 반올림은 **원 단위 사사오입(ROUND_HALF_UP)**이다. 금액 계산에는 부동소수점을 쓰지 않는다(정수·10진 고정소수점).

- **줄 금액** = round(수량 × 단가 × 적용률 ÷ 100)
  - 적용률은 0~100이고 소수 둘째 자리까지다. 기본값은 100이다.
  - ③ 비용 분리는 단가 = 재료비 + 노무비 + 경비다.
  - ①②④⑤는 단가 = `price`다.
- **품목 합계(subtotal)** = 줄 금액의 합. 줄마다 먼저 반올림한 뒤 더한다.
- 종류별 계산
  - ① 부가세 표시(`vat`)와 ③ 비용 분리(`cost`): 부가세 = round(subtotal × 0.1), 견적가 = subtotal + 부가세.
  - ② 부가세 미포함(`total`): 부가세 0, 견적가 = subtotal.
  - ④⑤(`catalog`, `catalog2`): 부가세 0이고, 단가는 부가세 포함 금액이다.
    - **subtotal ≥ 50,000,000이면** 견적가 = round(subtotal × 0.98), 아니면 견적가 = subtotal. 경계값 50,000,000원 정확히는 할인한다.
    - 조달수수료 = round(할인 후 금액 × 0.0054)를 계산하지만 **견적가에 더하지 않는다**.
- 견적가가 9,999,999,999,999를 넘으면 오류를 낸다: "견적 합계가 지원 범위를 초과합니다."
- ③ 자동 계산
  - 노무비 자동값 = round(재료비 × 2.8125), 경비 자동값 = round(노무비 × 0.03).
  - 줄마다 '노무비 자동', '경비 자동' 상태가 있고, 새 줄은 둘 다 켜져 있다.
  - 노무비나 경비를 직접 입력하면 해당 자동 상태가 꺼진다. '자동으로 복원'을 누르면 다시 켜지고 즉시 다시 계산한다.
  - 경비 자동값은 현재 노무비 값(자동이든 직접 입력이든)을 기준으로 계산한다.
- 화면 하단 합계는 서버 계산과 같은 규칙으로 실시간 표시한다.
  - 표시 항목: ①③은 공급가액·부가세·견적가, ②는 견적가, ④⑤는 품목 합계·견적가.
- 기준 정답은 기존 `nrobot_full/web_quote/core/quote.py`의 `calculate`, `line_amount`, `catalog_totals`다. 같은 입력에서 결과가 1원이라도 다르면 실패다.

## 8. 입력 검증 (서버. 기존 `validation.py` 규칙 그대로)

**생성 요청 본문(`POST /api/generate`)**: 다음 필드만 쓴다. 나머지 필드는 무시한다.

| 필드 | 형식 |
|---|---|
| `format` | `"pdf" \| "xlsx"` (요청 1회에 파일 1개) |
| `quoteType` | `"vat" \| "total" \| "cost" \| "catalog" \| "catalog2"` |
| `customer`, `contact`, `phone`, `email`, `title`, `validity`, `delivery`, `payment` | 문자열 |
| `date` | `"YYYY-MM-DD"` |
| `number` | 문자열 (브라우저가 확정한 견적번호) |
| `staffId` | 문자열. 서버가 `STAFF_CONFIG`에서 찾는다. 없으면 "작성자를 선택하세요." 표시 이름은 서버 설정값을 쓴다 |
| `staffPhone` | 문자열 30자 이하 (화면의 현재 값) |
| `notes` | 문자열 1개 (참고사항 한 칸) |
| `showFee`, `mergeCategories`, `blankRows` | 불리언 |
| `catalogRevision` | 문자열 (④⑤) |
| `items[]` | `{ category, name, unit, qty, price, priceRate, material, labor, expense, note, catalogId, imageIds }`. ③은 material·labor·expense를 쓰고 price는 무시한다. ①②④⑤는 price를 쓴다. `autoLabor`·`autoExpense`·직접 입력 번호 여부는 화면 상태라 서버로 보내지 않아도 된다 |

화면의 '저장 형식'(`pdf | xlsx | both`)은 화면이 요청 횟수를 정하는 데만 쓴다.

- 견적 종류는 위 5가지다.
- 문구 필드(customer, contact, phone, email, title, number, validity, delivery, payment)
  - 문자열 500자 이하이고, 앞뒤 공백을 지운다.
  - **거래처(customer)와 견적 제목(title)은 필수**다.
- 작성일은 `YYYY-MM-DD`이고 실제 날짜여야 한다. 아니면 "작성일을 YYYY-MM-DD 형식으로 입력하세요."
- 품목
  - 1~100개.
  - 품목명·구분·단위·비고는 500자 이하다(④⑤는 10,000자 이하). **품목명과 단위는 필수**다.
  - 수량: 0 < 수량 ≤ 1,000,000, 소수 셋째 자리까지.
  - 단가: 0 ≤ 단가 ≤ 100,000,000,000 정수. ③에서는 단가를 쓰지 않는다.
  - 적용률: 0~100, 소수 둘째 자리까지.
  - ③의 재료비·노무비·경비는 각각 필수이고 0~100,000,000,000 정수다. 없는 비용은 0이다.
- 참고사항은 한 칸이고 2,000자 이하다.
- 옵션 기본값: 조달수수료 표시 ON, 같은 구분 묶기 ON, 빈 행 2줄 추가 ON.
- 오류 메시지는 기존 문구를 따른다. 예: "{n}번 수량은 양수(소수 셋째 자리까지), 단가는 0 이상의 정수로 입력하세요."
  - 화면에서 같은 검사를 먼저 하지만, 서버 검사가 최종이다.
- 출력 시 유효기간·납품·결제 앞에 각각 "견적 유효기간 : ", "납품 : ", "결제 : "를 붙인다.

## 9. 견적번호 (확정 — 브라우저별 발급, 나중에 DB로 교체)

- 형식: `NSFF0-YYYYMMDD-NNN`. 날짜는 작성일, NNN은 3자리 일련번호다.
- 다음 번호 계산(기존 `numbering.py`와 동일)
  1. 그 날짜에 그 담당자가 이미 받은 가장 큰 번호를 찾는다.
  2. 다음 번호 = max(담당자 시작 번호, 그 번호 + 1). 받은 번호가 없으면 시작 번호다.
  3. 그 날짜에 이미 쓰인 번호(다른 담당자 것과 직접 입력한 번호 포함)는 건너뛴다.
  4. 999를 넘으면 "해당 날짜의 견적번호를 모두 사용했습니다." 오류를 낸다.
  - 담당자별 구간은 시작점일 뿐 엄격하지 않다. 예: 시작값 001인 담당자가 10건을 넘기면 010이 비어 있을 때 010을 쓰고, 시작값 010인 담당자는 011부터 받는다. 하루 5건 정도라 문제없다(사용자 확인).
- 자동으로 만든 번호는 화면에서 직접 고칠 수 있다.
  - 고치면 '직접 입력' 상태가 된다. 작성일이나 작성자를 바꾸면 다시 자동 번호로 돌아간다.
  - 직접 입력 번호는 1~100자이고 제어문자를 쓸 수 없다.
  - 직접 입력 번호가 그 브라우저의 발급 이력(직접 입력 이력, 그리고 `NSFF0-날짜-NNN` 형식이면 그 날짜·번호)과 겹치면 "이미 발급된 견적번호입니다. 다른 번호를 입력하세요."라고 거부한다.
- **번호는 파일 생성에 성공했을 때만 발급 이력에 기록한다.** 실패하면 번호를 쓰지 않은 것으로 친다.
- '두 형식 함께 저장'은 PDF와 Excel이 **같은 번호**를 쓴다. 둘 다 성공해야 번호를 기록한다.
- 발급 이력은 브라우저 저장소에 둔다.
  - 다른 PC·브라우저끼리는 번호가 겹칠 수 있고, 같은 브라우저의 여러 탭이 동시에 받아도 겹칠 수 있다. 시연판에서는 허용한다(사용자 확인).
  - 저장 방식은 교체 가능한 하나의 경계 뒤에 둔다. 예: `previewNext(date, staffId)`, `checkManual(number)`, `record(...)`.
  - 나중에 서버 DB로 바꿀 때는 그 경계의 구현만 바꾼다. 화면 코드와 계산 코드는 바꾸지 않는다.

## 10. 출입통제 기준가격표 (①②③ 품목 선택)

**해석 규칙** (기존 `access_catalog.py` 그대로)
- 모든 시트에서 셀 값에 `품목`·`제품명`·`단가`가 모두 있는 행을 머리글로 본다. 그 아래 행 중 `품목`이 있는 행을 하나의 항목으로 읽는다.
  - 단가가 숫자가 아니거나 0~100,000,000,000 범위를 벗어나면 빌드가 실패한다: "{시트} {행}행의 부가세 별도 단가를 확인하세요."
  - 단가는 원 단위로 반올림한다.
- 항목 필드
  - `id = "{시트명}:{행번호}"`. 같은 모델도 행마다 별도 항목이다.
  - `title`(품목), `model`(제품명), `category`(소요군), `note`(비고), `price`.
  - `name` = title, 모델명이 있으면 `title + "\n" + model`(미리보기용). `qty` = 1.
  - `costBucket`: 품목에 `설치`·`철거`·`배관배선` 중 하나가 들어 있으면 `labor`, 아니면 `material`. `이전설치`는 `설치`를 포함하므로 labor다.
  - `unit`: labor면 `식`, 아니면 `대`.
- 압축 해제 크기가 50MB를 넘으면 실패한다.
- 항목이 하나도 없으면 실패한다: "품목·제품명·단가 열이 있는 가격표를 확인하세요."
- `revision` = 원본 엑셀 파일 바이트의 sha256.

**화면 동작** (기존 `access_ui.js` 그대로)
- 소요군 필터: 전체 + 목록. **검색 필터로만 쓰고 품목에는 넣지 않는다.**
- 검색은 품목·모델·소요군·비고를 대상으로 하고 대소문자를 구분하지 않는다.
- 결과가 하나면 자동으로 선택한다. 미리보기에는 이름, "부가세 별도 {단가}", 비고, "3번 견적 입력 위치: 노무비/재료비"를 보여 준다.
- '선택 품목 추가'(①②③에서만)를 누르면 이렇게 새 줄을 만든다.
  - 구분 = 품목 종류(`title`), **품목명 = 모델명**. 모델명이 없으면 품목 종류를 품목명에 넣는다.
  - 단가 = price. ③에서는 costBucket이 material이면 재료비 = price, labor면 노무비 = price이고, 나머지 비용은 0이다.
  - 이렇게 추가한 줄은 노무비·경비 자동 상태가 꺼져 있다.
  - 적용률 100, 수량 1, 단위는 항목 단위를 넣는다.
- 품목 목록이 빈 줄 하나뿐이면 그 줄을 대체한다. 100개를 넘으면 "품목은 최대 100개입니다."라고 표시한다.
- 같은 품목을 여러 번 추가할 수 있다. 추가한 줄의 모든 값은 자유롭게 고칠 수 있고, 가격표와 연동되지 않는다.

## 11. 영업팀 제품가격표 (④⑤ 품목 연동)

**해석 규칙** (기존 `catalog.py`·`excel_style.py` 그대로. 바꾸지 않고 옮긴다)
- 시트마다 21행부터 C·F·G열이 모두 채워진 행을 품목 시작 행으로 본다. 다음 시작 행 직전, 마지막 품목은 A열에 '합계'(공백 무시)가 있는 행 직전까지가 한 품목이다.
- 품목 필드
  - `title` = 첫 C 셀, `name` = 범위 안 C 셀들을 줄바꿈으로 잇는다.
  - `category` = B열(비면 앞 품목 값을 이어받고, 그것도 없으면 시트명).
  - `unit` = F, `qty` = G, `price` = H.
  - `note` = J열 줄들, `internalNote` = K열 줄들.
- 모델명 추출: 둘째 줄부터 **한 줄씩 차례로** 본다. 먼저 걸리는 줄이 이긴다.
  - 그 줄에 '모델명'이 있으면: '모델명' 뒤(':'·'：'와 공백 제거) 텍스트의 첫 '/' 앞.
  - 아니고 그 줄이 `영숫자-영숫자`로 시작하면: 그 줄의 첫 '/' 앞.
  - 둘 다 아니면 다음 줄로 넘어간다.
  - `code` = 모델명 맨 앞에서 `[A-Za-z0-9][A-Za-z0-9+_.-]*`에 맞는 부분. 없으면 모델명 전체.
- 단가
  - H가 수식이면 `price = null`이고 경고를 남긴다: "{시트}!H{행}: 수식 단가는 최신 계산 여부를 확인할 수 없어 직접 입력이 필요합니다."
  - H가 비어 있으면 `price = null`이고 경고는 남기지 않는다.
  - 값이 있는데 0 이상의 정수가 아니면 `null`이고 "{시트}!H{행}: 단가 확인 필요" 경고를 남긴다.
- `id` = sha256(시트명 + "\0" + 모델명 + "\0" + 첫 줄)의 앞 24자. 같은 값이 이미 있으면 `-{시작행}`을 붙인다.
  - 시트·모델명·첫 줄이 같은 다른 품목이 없는 한, 가격표를 다시 배포해도 같은 품목은 같은 id를 유지한다.
  - 중복 때문에 행 번호가 붙은 id는 행이 밀리면 바뀐다. 기존과 같고, 이때는 '사라진 제품'으로 처리된다.
- 시트 조건 문구(`terms`)
  - D16·D17·D18의 ':' 뒤 텍스트를 각각 유효기간·납품·결제로 쓴다.
  - 합계 행 아래에서 `숫자.`로 시작하는 A열 줄들을 참고사항으로, J16을 수수료 문구로 쓴다.
- 서식 템플릿(PDF·Excel 재현용)
  - 열 너비(A~J, 숨김 열은 0), 품목 범위 행 높이 합.
  - C열 각 줄의 글꼴·크기·굵기·색·채움·정렬(테마 색과 tint 반영).
    - tint 계산의 반올림은 기존 Python `round()`와 같은 **짝수 반올림(banker's rounding)**이다. 사사오입이 아니다.
  - A·B·F·G·H·I·J 셀 서식, C20 머리글 서식과 20행 높이.
- 사진
  - 그림 앵커가 J열 이내이고 가로·세로가 100000 EMU 이상인 것만 쓴다. 해당 행을 포함하는 품목에 붙인다.
  - `srcRect` 자르기를 적용한다.
  - 원래 표시 크기(EMU ÷ 12700 pt)를 템플릿에 기록한다.
  - 사진 id는 변환한 이미지 내용의 sha256이다.
- 품목이 하나도 없으면 빌드가 실패한다: "제품 표를 찾지 못했습니다…"
- **사진 축소(확정)**: Vercel 응답 한도(약 4.5MB) 안에서 항상 생성되도록 빌드 단계에서 인쇄에 충분한 해상도로 줄인다.
  - 기본값: 긴 변 최대 600px, 품질 85의 JPEG. 투명 배경이 있으면 PNG를 쓴다. 이 값은 조정 가능하다.
  - 지면에 찍히는 크기와 위치는 원래 표시 크기를 따른다.
- 가격표 `revision` = 변환 결과 내용의 해시.

**화면 동작** (기존 `catalog_ui.js` 그대로 + 변경 알림 추가)
- 검색은 모델명·품목명·시트명을 대상으로 하고 대소문자를 구분하지 않는다.
  - 코드·모델명·품목명이 정확히 같은 항목이 하나면, 또는 결과가 하나면 자동으로 선택한다.
- 미리보기에는 이름, "단가(부가세 포함): {단가 또는 '직접 입력 필요'} / {단위}", 비고, 내부 참고, 사진을 보여 준다.
- '선택 제품을 품목에 추가'를 누르면 연동된 줄이 생긴다.
  - 품목명·구분·단위·비고·단가가 가격표 값이다. 단가가 null이면 단가만 직접 입력한다.
  - 수량 초기값은 가격표 G열 값이다(기존과 같음).
  - 연동 중인 칸은 읽기 전용이다. 수량과 적용률은 고칠 수 있다.
  - 품목 목록이 빈 줄 하나뿐인 상태에서 **첫 제품을 추가하면**, 그 시트의 조건으로 유효기간·납품·결제를 채운다. 제목이 비어 있으면 품목 첫 줄을 제목으로 넣는다.
  - 같은 경우 참고사항은 "1. 해당 건에 대한 견적가격입니다." 뒤에 시트 참고사항들과 수수료 문구를 번호를 다시 매겨 넣는다. 수수료 문구의 "조달수수료(0.54%) 총계 포함/합계 포함/포함/별도"는 "조달수수료(0.54%) 별도"로 바꾼다.
- '복제'를 누르면 바로 아래에 같은 줄(연동 상태 포함)을 추가한다. 수량은 각각 고칠 수 있다.
- '연동 해제'를 누르면 그 줄은 이후 가격표를 따르지 않고 모든 칸을 직접 고칠 수 있다.
- **가격표 변경 반영(확정)**: 화면을 열거나 저장된 입력내용을 불러왔을 때 연동된 줄이 현재 가격표와 다르면(품목명·구분·단위·비고·단가·사진 중 하나라도 다르면) **현재 가격표 값으로 바꾼다.**
  - 그리고 "가격표가 바뀌어 다음 품목이 갱신되었습니다: {n}번 …"이라고 바뀐 줄 번호와 바뀐 항목을 화면에 알린다.
  - 수량과 적용률은 유지한다.
- 연동된 줄의 품목이 현재 가격표에 없으면 그 줄에 "엑셀에서 제품이 삭제되거나 이름이 변경되었습니다. 다시 선택하세요."를 표시한다. 견적 생성은 거부한다.
- 서버 검증(④⑤)
  - 요청의 `catalogRevision`이 현재와 다르면 "제품 엑셀이 변경되었습니다. 최신 내용을 불러온 후 다시 만들어주세요."(기존 문구)로 거부한다.
  - 연동 id가 현재 가격표에 없으면 "{n}번 제품이 엑셀에서 삭제되거나 이름이 변경되었습니다. 다시 선택하세요."로 거부한다.
  - 연동된 줄은 서버가 가격표 값(품목명·구분·단위·비고, null이 아닌 단가, 템플릿, 사진)으로 덮어쓴다.
  - 연동되지 않은 줄의 사진 id는 현재 가격표에 있는 것만 남긴다.

## 12. 출력 — PDF (기존 `pdf_quote.py`와 거의 동일)

공통
- A4 세로. 좌우 여백 합 36pt를 뺀 폭 W를 쓴다.
- 글꼴: ①②③은 맑은 고딕(보통·굵게), ④⑤는 KoPub돋움체 Medium(굵은 글씨 자리도 Medium. 기존과 동일).
  - 글꼴 파일은 서버 함수에 포함한다. 맑은 고딕은 `private/fonts`에서, KoPub는 저장소에서 가져온다.
- 상단 구성
  - 큰 제목 "견       적       서".
  - 왼쪽 표: 견적번호, 수신, 참조, 작성일자 "YYYY년 M월 D일", TEL., FAX.(이메일 값). 머리 칸 배경 #f2f2f2.
  - 오른쪽 공급자 표
    - 상호 '주식회사 앤로보틱스', 대표 '김종서 [직인생략]', 사업자번호 '140-81-01965'.
    - 주소 '경기도 안양시 동안구 시민대로 109번길 11, 앤로보틱스' + 둘째 줄 '(안양사업장)'.
    - 연락처 'Tel. 031-429-0050, Fax. 031-429-0030', 담당자 표시 이름, H.P 휴대폰.
  - 1페이지 오른쪽 위에 로고 이미지 3개.
- "아래와 같이 견적서를 제출합니다", `품 명 : "{제목}"`.
- 특기사항·금액 표
  - 유효기간·납품·결제 3줄.
  - 금액: "일금{한글 금액}원정". 한글 금액은 일·이·삼 … 십·백·천·만·억·조로 쓴다. 십·백·천 자리의 1은 생략하고 0은 '영'이다.
  - 둘째 줄: ①②③은 "₩{견적가 쉼표}", ④⑤는 "{견적가 쉼표}원".
  - 셋째 줄: ②는 "V.A.T.(부가가치세) 미포함", 나머지는 "V.A.T.(부가가치세) 포함".
  - ④⑤는 오른쪽 끝에 칸을 하나 더 둔다. 조달수수료 표시 ON이면 "조달수수료(0.54%) 별도", OFF면 빈칸이다.
- 품목 표
  - 머리글: 순번·구분·품목·단위·수량·(①②④⑤ 단가 | ③ 재료비·노무비·경비)·합계·비고.
  - 수량 표기는 기존 Python `f"{qty:g}"`와 같다(유효숫자 6자리, 불필요한 0 제거. 예: 1.125 → "1.125", 3.0 → "3").
    - 7자리 이상에서 생기는 지수 표기("1e+06")만은 따라 하지 않고 일반 숫자로 쓴다. 이것은 기존과의 의도된 차이다.
  - 금액은 천 단위 쉼표로 쓴다.
  - 비고의 "조달 식별 번호 …숫자"는 "조달식별번호\n숫자"로 두 줄 표시한다.
- 같은 구분 묶기 ON
  - 연속해서 같은(공백 제거 후 비어 있지 않은) 구분인 줄은 순번·구분 셀을 병합한다.
  - 순번은 묶음 단위로 1부터 증가한다. 빈 구분은 항상 새 순번이다.
  - OFF면 줄마다 증가한다.
- 빈 행 2줄 추가 ON이면 마지막 순번 다음 번호 2개로 낮은 빈 행(16pt)을 추가한다.
- 합계 표
  - ①③: 합 계 / 부 가 세 / 견 적 가. 마지막 줄 노란색.
  - ②: 견 적 가(노란색).
  - ④⑤: "합 계" 한 줄(노란색)에 할인 반영 최종 금액.
- NOTE 칸(머리 #bfbfbf)에 참고사항을 넣는다.
  - ④⑤는 참고사항의 "조달수수료(0.54%) 총계 포함/합계 포함"을 "… 별도"로 바꾼다. 수수료 표시 OFF면 '조달수수료'가 든 줄을 지운다.
- 열 너비·글꼴 크기·행 높이 규칙은 기존 코드를 그대로 따른다.
  - ①②는 `base_layout.json` 비율, ③은 고정 비율, ④⑤는 가격표 템플릿 열 너비다.
  - ④⑤ 연동 줄은 템플릿의 줄별 서식·행 높이·사진 크기를 재현한다.
- 페이지
  - **①②③은 항상 1페이지**. 넘치면 전체를 비율로 축소한다.
  - **④⑤는 페이지당 최대 4품목**이고 품목 행을 페이지 중간에서 자르지 않는다. 2페이지부터 큰 제목·상단 표·특기사항 표를 뺀다. 합계·NOTE는 마지막 페이지에 둔다.
  - ④⑤ 모든 페이지 아래 가운데에 "{쪽} / {전체}"를 쓴다. 모든 페이지에 같은 축소 비율을 적용한다.
- 문서 속성: 제목 = 견적 제목, 작성자 = '주식회사 앤로보틱스'.

## 13. 출력 — Excel (기존 `xlsx_quote.py`와 거의 동일)

- 편집 가능한 xlsx를 만든다. 셀 배치는 PDF와 같은 구성을 좌표 격자로 재현한다.
  - ①②③은 시트 하나 '견적서'다.
  - ④⑤는 4품목마다 시트를 나눈다: '견적서', '견적서_2', …
- 글꼴 이름은 ①②③ '맑은 고딕', ④⑤ 'KoPub돋움체 Medium'이다. Excel에는 글꼴 파일을 넣지 않고 이름만 쓴다.
- **살아 있는 수식**(받은 사람이 값을 고치면 다시 계산됨)
  - 줄 합계: `ROUND(수량*(단가 또는 재료비+노무비+경비)*{적용률}/100,0)`.
  - ①③: 합계 `SUM(줄합계들)`, 부가세 `ROUND(합계*0.1,0)`, 견적가 `SUM(합계,부가세)`.
  - ②: `SUM(…)`.
  - ④⑤: `IF(SUM(…)>=50000000,ROUND(SUM(…)*0.98,0),SUM(…))`.
  - 상단 금액칸: `"일금 "&TEXT(최종,"#,##0")&" 원정"`과 `=최종`.
  - Excel 상단 금액 표기는 숫자("일금 1,234 원정")로, PDF의 한글 금액과 다르다. **기존과 같게 유지한다.**
  - 계산된 값도 함께 기록해서 열자마자 값이 보이게 한다.
  - 적용률 숫자 표기(`100` 또는 `100.0`)는 자유다. 검사는 수식 문자열의 글자 일치가 아니라 **구조와 계산 결과의 일치**로 한다.
- 수량 셀은 일반 형식(기존과 같음), 금액은 `#,##0`.
- 인쇄 설정: A4 세로, 한 장에 맞춤(폭·높이 1페이지). 눈금선 숨김, 확대 85%.
- 시트가 여러 개면 바닥글에 `{시트 번호} / {전체}`를 넣는다(기존과 같음).
- 사진(④⑤)은 비고 칸 안 같은 위치에 넣는다.
- 셀 값이 `=`, `+`, `@`로 시작하는 사용자 입력은 수식이 아니라 문자로 넣는다.

## 14. 파일 생성과 다운로드

- '만들기'를 누르면 화면은 다음 순서로 처리한다.
  1. 담당자 휴대폰 변경을 반영한다.
  2. ④⑤면 가격표 최신 여부를 확인한다.
  3. 번호를 확정한다.
  4. 서버에 형식별로 생성을 요청한다(`both`면 PDF와 Excel 요청 2회, 같은 번호).
- 서버는 파일을 만들어 **바로 응답으로 돌려준다. 서버에는 아무것도 저장하지 않는다.**
- 응답 파일 이름: `견적서_{안전한 거래처명}.pdf` / `.xlsx`.
  - 안전한 거래처명: `<>:"/\|?*`와 제어문자는 `_`로 바꾸고, 앞뒤 공백·마침표를 지운 뒤 40자로 자른다. 비면 '거래처'를 쓴다.
- 브라우저는 받은 파일을 내려받기로 저장한다. 성공하면 "견적서를 저장했습니다. {번호}"를 표시하고 번호 이력을 기록한 뒤 다음 번호를 다시 계산한다.
- 생성 중에는 입력과 버튼을 잠근다. 실패하면 "{오류}\n입력내용은 유지되어 있습니다."를 표시한다.
- 생성은 Vercel Hobby의 함수 실행 시간과 응답 크기 한도 안에서 끝나야 한다.
  - 100품목·사진 많은 ④⑤ PDF도 4.5MB 미만이어야 한다. 검사로 확인한다.

## 15. 화면

- 최초 접속 시 공용 비밀번호를 받고, 입장 후 `/`의 한국어 랜딩페이지를 보여 준다(2026-10-26 사용자 추가 요청). 랜딩페이지의 '견적서 작성'에서 `/quote`의 입력 화면으로 이동한다. 두 페이지 모두 기존 입장 보호를 적용하며, 서명 쿠키로 30일간 입장 상태를 유지한다. 나가기·비밀번호 변경·만료 시 다시 입장해야 한다.

  - 견적서 종류·저장 형식·조달수수료 표시.

## 16. 인수인계·배포 안내 문서 (확정)

지금은 사용자가 배포하지만, 나중에 회사 사람이 넘겨받아 혼자 배포·관리할 수 있어야 한다. 저장소에 다음 문서를 한국어로 둔다.

- `README.md`: 무엇인지, 기능, 사용 기술, 폴더 구조, 개발 시작(설치 → `private/` 준비 → `.env.local` → 실행), 확인 명령.
- `docs/배포가이드.md`: 처음 받는 사람이 처음부터 끝까지 따라 하면 배포되는 절차.
  - 준비물: Node 22, Vercel 계정, Vercel CLI.
  - `private/` 파일을 어디서 받아 어떤 이름으로 두는지. 가격표 원본 파일명, 맑은 고딕 파일 위치(Windows `C:\Windows\Fonts`).
  - 환경 변수 `APP_PASSWORD`·`STAFF_CONFIG`의 형식·예시·설정 방법(Vercel 화면, `vercel env`).
  - `vercel link` → `vercel pull` → `vercel build --prod` → `vercel deploy --prebuilt --prod`.
  - 자주 하는 일: 가격표 교체, 비밀번호 변경, 담당자 변경 → 다시 배포.
  - 문제 해결: 빌드가 `private/` 누락으로 실패할 때, 입장이 안 될 때, 생성이 실패할 때.
  - 주의
    - 무료(Hobby) 요금제는 개인·비상업용 조건이 있다. 회사가 정식으로 쓰면 유료(Pro) 전환을 검토한다.
    - 맑은 고딕 글꼴은 서버에 올려 쓰는 것이 라이선스상 문제가 될 수 있으므로 정식 운영 전에 회사가 판단해야 한다.
    - 견적번호는 브라우저별이라 PC끼리 겹칠 수 있다.
    - 개인정보와 회사 자료는 저장소에 올리지 않는다.
- `docs/사용방법.md`: 직원용 사용 순서(입장 → 종류 선택 → 품목 → 만들기 → 내려받기). 번호와 자동 저장의 성질도 적는다.
- `docs/릴리즈노트.md`: 이번 시연판 v0.1의 기능·제한·검증 결과. 이후 변경을 계속 덧붙인다.
- 안내 문서에도 실제 비밀번호·휴대폰·단가는 쓰지 않는다.

## 17. 불변 조건 (어기면 실패)

- 같은 입력에서 금액(줄 합계·합계·부가세·견적가)과 견적번호 계산 결과가 기존 Python과 1원·1자리도 다르지 않다.
- ①②③ PDF는 1페이지다. ④⑤ PDF와 Excel은 ⌈품목 수 ÷ 4⌉ 페이지(시트)이고, 한 품목이 두 페이지에 걸치지 않는다.
- 조달수수료는 어떤 경우에도 견적가에 더하지 않는다.
- 실패한 생성은 번호를 쓰지 않는다. '두 형식 함께'는 한 번호다.
- 비밀번호 없이는 페이지와 데이터, 생성 기능 어느 것에도 접근할 수 없다. `APP_PASSWORD`가 없으면 아무도 들어갈 수 없다.
- 저장소(git)에 실제 담당자 정보, 실제 가격표와 그 변환물, 맑은 고딕 파일, 비교용 실제 견적서가 들어가지 않는다.
- 빌드·실행은 `nrobot-web` 밖의 경로를 참조하지 않는다.

## 18. 필요한 검증

1. **기준 데이터(골든) 비교 — 자동**
   - 이 PC에 Python 3.12를 설치하고 기존 코드(`nrobot_full/web_quote/core`)를 실행한다. 사용자 승인을 받았다.
   - 합성 입력으로 기준 정답을 한 번 만들어 `nrobot-web` 저장소에 넣는다. 가짜 담당자만 쓴다.
   - 최소 범위
     - 5종 × 여러 품목 수(1·2·3·4·5·8·9·10·20·40·100).
     - 적용률(100·77·90·0·99.99), 소수 수량(1.125 등).
     - ③ 자동·수동 비용, 0원, 최대값 근처.
     - ④⑤ 할인 경계(49,999,999 / 50,000,000 / 50,000,001원), 반올림 경계(.5).
     - 견적번호: 담당자별 시작, 건너뛰기, 직접 입력 충돌, 실패 시 미소비, 999 초과.
     - 검증 오류 사례.
   - `npm test`가 새 코드 결과를 기준 정답과 비교해 전부 일치해야 한다. 이후 검사에는 Python이 필요 없다.
2. **가격표 해석 — 자동**
   - 저장소에 합성 시험 엑셀(출입통제·제품 형식 각 1개, 가짜 단가·작은 그림 포함)을 두고 해석 결과를 검사한다.

   - 자동: 페이지(시트) 수, 표의 금액 문자열, 수식 문자열, 파일 크기(4.5MB 미만)를 검사한다.
   - 사람 확인: 같은 입력으로 기존 Python이 만든 PDF와 새 PDF를 쪽마다 그림으로 바꿔 나란히 놓은 비교 이미지를 `private/compare/`에 만든다. `private/reference/`의 기존 예시 5종과 같은 내용으로 만든 새 결과도 함께 넣는다.
   - 사용자가 눈으로 보고 승인한다. 승인 전에는 '모양 확인 완료'로 기록하지 않는다.
4. **입장 비밀번호 — 자동**
   - 비밀번호 없이 페이지·API에 접근하면 막히는지 확인한다.
   - 틀린 비밀번호, 맞는 비밀번호, 비밀번호 변경 후 기존 쿠키 무효, `APP_PASSWORD` 미설정 시 전원 차단을 확인한다.
5. **저장소 경계 — 자동**: `git ls-files`에 `private/`, `.env.local`, 실제 가격표 변환물, `malgun*.ttf`가 없음을 검사한다.
