## 문서 역할과 충돌 해결

| 문서 | 역할 |
|---|---|
| `.dryforge/spec.md` | **무엇을 만드는가 — 기준(ground truth).** 충돌하면 spec이 이긴다. spec 오류는 사용자 승인으로만 고친다. |
| `.dryforge/plan.md` | 작업 순서·대상·검증(임시 설계도). 자유롭게 고쳐도 되지만 spec을 어기면 안 된다. |

## 실행의 큰 그림

빈 Next.js 프로젝트에서 시작한다. 진행 순서는 다음과 같다.
1. 기존 Python으로 **기준 정답**을 만든다.
2. 그 정답에 맞춰 계산·번호·가격표 해석을 옮긴다.
3. 그 위에 PDF와 Excel 생성기를 얹는다.
4. 입장 비밀번호, API, 화면을 붙인다.
5. 모양을 비교하고 배포 준비와 안내 문서로 마무리한다.

## 꼭 지킬 규칙 (코드만 보고는 알 수 없는 것)

1. **기존 계산식·번호 규칙은 한 글자도 바꾸지 않는다.**
   - 사사오입은 원 단위로 한다. 줄마다 먼저 반올림한 뒤 더한다. 부가세는 품목 합계에 붙인다.
   - ④⑤는 품목 합계 50,000,000원 이상이면(같을 때 포함) 2% 할인한다. 조달수수료 0.54%는 절대 더하지 않는다.
   - 금액에 부동소수점을 쓰지 않는다.
   - 기준 정답(기존 Python 출력)과 1원이라도 다르면 그 작업은 실패다. 정답을 고쳐 맞추는 것은 금지다.
2. **개인정보·회사 자료는 git에 절대 들어가지 않는다.** 실제 담당자 정보, 실제 가격표와 그 변환물, 맑은 고딕, 비교용 실제 견적서가 대상이다.
   - 커밋 전에 `git ls-files`로 확인한다.
   - 소스·기준 데이터·문서·검사 코드에 실제 휴대폰 번호와 실제 단가를 쓰지 않는다. 기존 코드의 휴대폰 기본값도 옮기지 않는다.
3. **`nrobot-web`이 유일한 원본이다.** 빌드·실행·검사 코드가 `nrobot-web` 밖의 경로를 참조하면 안 된다.
   - 예외: 기준 정답을 만드는 일회성 도구가 `nrobot_full`을 읽는 것.
4. **비밀번호 없이는 아무것도 열리지 않는다.** 모든 페이지와 API가 대상이다. `APP_PASSWORD`가 없으면 전원 차단한다(실패 시 닫힘).
5. **서버에 아무것도 저장하지 않는다.** 서버는 상태가 없다. 번호 이력·입력내용·휴대폰 수정값은 브라우저에만 둔다.
   - 번호 저장은 교체 가능한 경계 뒤에 둔다. 나중에 DB를 붙일 자리다.
6. **기존 코드(`nrobot_full`)는 읽기 전용이다.**
7. 모양 비교는 사용자가 눈으로 승인해야 완료다. 자동 검사 통과만으로 '모양 확인 완료'라고 기록하지 않는다.
8. **실제 Vercel 업로드는 하지 않는다.** `vercel build` 성공까지만 한다.
   - 이 PC에 Vercel CLI가 없거나 로그인이 필요해 `vercel build`를 할 수 없으면 멈추고 사용자에게 알린다.
9. 각 작업의 검증 기준: 확인 명령 `npm run lint && npm run typecheck && npm test && npm run build`가 종료 코드 0이어야 한다.
   - 단, `build`는 `private/`가 있어야 성공한다. 이 PC에서는 go가 미리 복사해 둔다.

## 작성 중 정해졌지만 spec·plan에 담기지 않은 의도

- **새로 만드는 이유**: 기능을 바꾸려는 게 아니다. **코드 정리와 사용 기술을 명확히 하기 위해서다.** 규칙은 그대로 옮기고 구조만 깔끔하게 한다. 기존 기능을 '개선'한다며 바꾸지 않는다.
- **맑은 고딕을 PDF에 넣는 결정**
  - 사용자는 무료 글꼴 대체를 먼저 골랐다가, PDF도 맑은 고딕이기를 원해 바꿨다. 라이선스 위험은 회사가 판단하기로 했다.
  - 안내 문서와 처리 못 한 문제 목록에 "정식 운영 전 재검토"로 남긴다.
  - 글꼴 지정은 한곳에 모아 두어, 나중에 파일만 바꾸면 다른 글꼴로 바뀌게 한다.
- **가격표·글꼴을 저장소에서 뺀 이유**: 이 프로젝트는 사용자가 임시로 만들어 회사 사람에게 넘겨준다. 그래서 GitHub 연결 배포 대신 이 PC에서 `vercel build` → `vercel deploy --prebuilt`로 올린다. `private/`가 빌드 결과에 포함되어야 한다.
- **견적번호를 브라우저에 두는 이유**: Vercel에는 서버 저장 공간이 없고, 시연용이라 번호가 겹쳐도 괜찮다. 사용자는 "나중에 DB 붙일 것"이라고 했다.
- **무료(Hobby) 요금제에 맞춘 이유**: 임시 시연이다. 함수 실행 시간과 응답 크기(약 4.5MB)를 넘지 않게 제품 사진을 빌드 단계에서 줄인다.
- **계획 문서 커밋**
  - 사용자는 "웹 폴더에서 계획 문서를 만들고 그것만 커밋해서 올리자"고 했다.
  - 승인 후 이 세 문서의 사본을 `nrobot-web/계획/`에 두고 그것만 첫 커밋으로 원격 `origin`(비공개 `YongWookLEE/nrobot`)에 올린다. `.dryforge/` 원본은 커밋하지 않는다.
  - 사본에도 개인정보는 없다(이 문서들에는 실제 휴대폰·단가가 없다).
- 기존 `nrobot_full`의 '작업기록 8종·다른 PC 바탕화면 복사본 갱신' 규칙은 이 프로젝트에 가져오지 않는다. 사용자용 릴리즈노트와 사용 안내만 유지한다.

## 프로젝트 기반 (Project Foundation)

> **실행 대상이 아닌 프로젝트 맥락이다.** go는 이 절을 맥락으로 읽고, 작업 마무리 때 프로젝트 문서를 만드는 재료로 쓴다. 구현 대상은 spec이다. 위의 '꼭 지킬 규칙'과 혼동하지 않는다.

### 1. 프로젝트 정체성

- (주)앤로보틱스(출입통제·RFID·로봇 장비 공급, 경기 안양)의 영업 담당자가 쓰는 **견적서 작성 웹앱**이다. 거래처와 품목을 넣으면 회사 양식의 PDF·Excel 견적서를 만든다.
- 사용자는 영업 담당자 3명 정도이고, 하루 견적은 5건 안팎이다.
  - 동시에 쓰는 사람과 데이터 양이 매우 작다. 무거운 서버 구조, 대기열, 캐시 계층은 필요 없다.
- 현재 단계는 **시험·시연용 임시 배포본(v0.1)**이다.
  - 개인 개발자(사용자)가 만들어 회사 담당자에게 넘긴다.
  - Vercel 무료 요금제에 올리고, 공용 비밀번호 하나로 막는다.
- 제약
  - 결과물은 기존 PC 프로그램 v29.3과 웹 1.0의 PDF·Excel과 거의 같아야 한다(거래처에 나가는 문서).
  - 개인정보·회사 단가는 저장소 밖에 둔다.
  - 서버는 상태가 없다.
  - 이전 세대(Windows EXE, Flask 웹 1.0)는 보관만 하고 더 개발하지 않는다. 웹으로 완전히 전환한다.

### 2. 도메인 모델

**견적서(Quote)**
- 한 번의 생성 요청으로 만들어지는 거래처용 문서다.
- 구성: 종류 1개, 작성자 1명, 거래처 정보, 제목, 작성일, 견적번호 1개, 조건 3줄(유효기간·납품·결제), 참고사항 1칸, 품목 1~100개, 옵션 3개(수수료 표시, 같은 구분 묶기, 빈 행).
- 서버에 저장되지 않는다. 생성 즉시 파일로만 존재하며, 화면 입력은 브라우저 초안으로 남는다.
- 같은 내용으로 다시 만들면 새 번호를 받는다.
- PDF와 Excel을 함께 만들면 같은 번호의 두 파일이 된다. 만든 뒤 Excel을 고쳐도 PDF나 화면과 자동으로 맞춰지지 않는다.
- 견적서 '수정·취소·재발행 이력'이라는 개념은 아직 없다.

**견적서 종류**: 다섯 가지이고 서로 계산이 다르다.
- `vat`(부가세 표시): 단가는 부가세 별도이고, 합계에 부가세 10%를 따로 표시해 더한다.
- `total`(부가세 미포함): 품목 합계만 낸다.
- `cost`(비용 분리): 단가를 재료비·노무비·경비로 나눈다. 부가세 10%를 더한다.
- `catalog`(영업1팀 제품)와 `catalog2`(영업2팀 제품): 계산과 양식이 동일하고 팀 구분만 다르다.
  - 제품가격표의 부가세 포함 단가를 쓴다. 5천만 원 이상이면 2% 할인한다.
  - 조달수수료 0.54%는 '별도' 안내만 하고 더하지 않는다.
  - 페이지당 4품목이다.
- 출입통제 가격표는 ①②③에서만, 제품가격표는 ④⑤에서만 쓴다.

**품목(Item)**
- 견적서의 한 줄이다. 필드: 구분, 품목명(여러 줄), 단위, 수량, 단가(또는 재료비·노무비·경비), 적용률, 비고.
- 적용률은 할인율의 반대다. 100%는 정상가, 77%는 23% 할인이다. 계산에만 쓰고 출력에는 나타나지 않는다.
- ③에서는 줄마다 '노무비 자동'(재료비×281.25%)과 '경비 자동'(노무비×3%) 상태가 있다. 직접 입력하면 꺼지고, 복원하면 켜진다.
- 줄의 출처는 셋 중 하나다.
  - (a) 직접 입력.
  - (b) 출입통제 가격표에서 복사. 복사 후에는 독립적이다.
  - (c) 제품가격표 연동. 가격표를 따르고, 연동 해제하면 (a)가 된다.
- 연동된 줄의 원본 제품이 가격표에서 사라지면 그 견적은 만들 수 없다. 원본 가격·규격이 바뀌면 새 값으로 바뀌고 사용자에게 알린다.

**담당자(Staff)**
- 견적서에 찍히는 작성자다. 필드: 이름, 직급, 휴대폰, 하루 번호 시작값.
- 현재 3명이다. 시작값은 001, 010, 020이다.
- 누가 화면을 쓰든 어떤 담당자든 고를 수 있다. 대신 작성하는 경우가 있다.
- 명단은 배포 설정에서 바꾸고, 휴대폰은 화면에서 고쳐 그 브라우저에만 기억한다.

**견적번호**
- `NSFF0-작성일8자리-일련번호3자리`. 작성일 기준으로 날마다 다시 시작한다.
- 담당자 시작값은 구간이 아니라 출발점이다. 하루 5건 정도라 겹칠 일이 드물어서 엄격하지 않아도 된다.
- 이미 쓴 번호는 건너뛰고, 직접 입력할 수 있으며, 중복 직접 입력은 거부한다.
- 실패한 생성은 번호를 쓰지 않는다.
- 현재는 브라우저별로 발급하므로 PC끼리 겹칠 수 있다. 서버 DB로 옮기면 전체 중복이 없어지는 것이 목표 상태다.

**출입통제 기준가격표**
- 회사가 관리하는 엑셀이다. 소요군·품목·제품명(모델)·단가(부가세 별도)·비고로 되어 있고, 현재 21개 품목이다.
- 같은 모델도 행마다 다른 항목이다(예: EM-Lock).
- 설치·철거·이전설치·배관배선은 '노무비 성격', 나머지는 '재료비 성격'이다.
- 소요군은 고르는 데만 쓰고 견적서에는 찍히지 않는다.

**영업팀 제품가격표**
- 회사의 견적서 양식 엑셀(약 16MB)이다. 시트마다 제품군이 있고, 품목별 여러 줄 규격·단가(부가세 포함)·비고·사진·서식이 있다.
- 시트별 조건 문구가 있다: 유효기간·납품·결제·참고사항·수수료 문구.
- 단가 칸이 수식이면 믿을 수 없으므로 직접 입력을 요구한다.
- 이 엑셀의 서식(글꼴·색·행 높이·사진 크기)이 ④⑤ 출력 모양의 원본이다.

**용어 구분**
- '구분'은 견적서 품목의 분류 칸이다.
- '소요군'은 출입통제 가격표의 필터용 분류다.
- '품목 종류'(가격표의 '품목' 열)는 출입통제 품목을 추가할 때 '구분' 칸에 들어간다.
- '합계'는 품목 표에서는 줄 금액, 하단 표에서는 품목 합계다. ④⑤의 하단 '합 계'는 할인 반영 최종 금액이다.

### 3. 기술 결정 (사용자 확인)

- **구조**
  - Next.js(App Router) + TypeScript 단일 앱이다. 화면과 서버 API가 같은 프로젝트에 있다.
  - 서버 API는 Node 런타임 함수로, 상태가 없다.
  - 가격표는 빌드 전 단계에서 데이터와 사진으로 변환해 함께 배포한다. 가격표가 바뀌면 파일을 바꾸고 다시 배포한다.
  - PDF(PDFKit)와 Excel(ExcelJS)은 서버에서 만들어 바로 내려준다.
  - 계산·번호·검증 같은 도메인 규칙은 화면과 서버가 함께 쓰는 하나의 순수 모듈에 둔다. 화면 미리보기와 서버 결과가 어긋나지 않게 하기 위해서다.
- **보안 모델**
  - 공용 비밀번호 하나(환경 변수)이고 개인 계정은 없다.
  - 모든 페이지와 API를 막는다. 서명 쿠키 30일이고, 비밀번호를 바꾸면 전원 재입장이다. 비밀번호를 설정하지 않으면 전원 차단한다.
  - 권한 구분(관리자·직원)과 감사 기록은 없다(시연판).
  - 개인정보(담당자 연락처)는 환경 변수, 회사 자료는 `private/`에 두고 git에서 뺀다.
- **규칙(최소)**
  - TypeScript strict, ESLint, Vitest.
  - 도메인 모듈은 프레임워크 코드에 의존하지 않는다.
  - 출력 생성기는 도메인 모듈만 의존한다.
  - 저장소 경계 검사는 자동화한다.
- **운영**
  - Vercel Hobby에 이 PC에서 직접 올린다(`vercel build` → `vercel deploy --prebuilt`).
  - 환경 변수: `APP_PASSWORD`, `STAFF_CONFIG`.
  - 저장소: 비공개 GitHub `YongWookLEE/nrobot`(이 폴더가 루트).
