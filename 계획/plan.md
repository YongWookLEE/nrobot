# plan — 앤로보틱스 웹 견적서 (임시 시연판)

spec이 기준이다. 이 계획은 spec을 실현하는 임시 설계도다. 경로는 `nrobot-web` 기준이다. 폴더 이름은 예시이며, 같은 경계를 지키면 바꿔도 된다.

## 전체 흐름

1. **T1**: 기존 Python으로 기준 정답을 만든다.
2. **T2**: 순수 도메인(계산·검증·한글 금액·순번 묶음)과 공용 타입.
3. **T3·T4·T7**을 동시에 진행한다.
   - T3: 견적번호 경계
   - T4: 가격표 변환
   - T7: 입장 비밀번호와 담당자 설정
4. **T5·T6**: PDF와 Excel 생성기.
5. **T8**과 **T10**: 서버 API, 모양 비교와 출력 검사.
6. **T9**: 화면.
7. **T11**: 배포 준비와 안내 문서.

**공용 파일 주의**: 의존성 설치, `package.json` 스크립트, `.gitignore`, `tsconfig`는 go가 미리 끝낸다.
- 각 작업은 `package.json`의 의존성 목록을 고치지 않는다. 추가 의존성이 꼭 필요하면 작업 보고에 적고, 웨이브 끝 연결 단계에서 한 번에 넣는다.
- 도메인 타입 파일(`src/domain/types.ts`)은 **T2가 단독으로 만든다**. 다른 작업은 읽기만 한다.

## T1 — 기준 정답(골든) 생성 도구

**목표**: 기존 Python 코드를 그대로 실행해, 새 코드가 맞춰야 할 정답을 만든다.

**작업 대상**
- 이 PC에 Python 3.12를 설치한다(winget). `reportlab==4.4.9`, `Pillow==12.3.0`도 설치한다.
- `tools/golden/`: Python 생성 스크립트와 합성 입력 정의.
- `tests/golden/*.json`: 저장소에 넣는 결과.
- `private/golden/`: 실제 가격표에서 뽑은 결과. 저장소 밖이다.

**동작 계약**
- `nrobot_full/web_quote/core`를 **읽기 전용**으로 불러 쓴다. 경로는 인자로 받는다.
- 기존 코드가 담당자 파일·데이터 폴더를 쓰는 부분은 환경 변수로 임시 폴더를 가리키게 한다. 원본 폴더에 아무것도 쓰지 않는다.
- 합성 입력은 가짜 담당자(가짜 이름·`010-0000-000N`)만 쓴다. 실제 휴대폰 번호를 쓰지 않는다.
  - 기존 코드는 담당자 이름을 키로 박아 두었다(`numbering.STARTS`, `staff_settings.KEYS`, `validate`의 휴대폰 기본값). 그래서 생성 스크립트가 실행 중에 메모리에서 이 값들을 가짜 담당자(시작값 1/10/20)로 덮어쓴다.
  - 요청에는 항상 `staffPhone`을 넣어 기본값이 쓰이지 않게 한다.
  - 정답 파일에는 새 요청 형식(spec 8절 표)으로 바꾼 입력을 함께 저장한다. 담당자는 `staffId`, 참고사항은 문자열 하나다. T2가 그대로 비교에 쓴다.
- 만드는 정답
  1. **계산**: spec 18절 1항의 범위 전부. 입력마다 `calculate` 결과(합계·부가세·견적가)와 줄별 `line_amount`를 기록한다.
  2. **검증**: `validation.validate`로 정상 입력의 정규화 결과(접두어 붙은 조건 문구 등)와 오류 입력의 오류 메시지를 기록한다. 가격표 연동 의존 부분은 제외하거나 합성 가격표로 대체한다.
  3. **견적번호**: 임시 sqlite로 `numbering`의 시나리오를 실행해 기록한다. 시나리오는 담당자별 첫 번호, 연속 발급, 다른 담당자 번호 건너뛰기, 직접 입력 충돌, 실패 시 미소비, 999 초과다.
     - 담당자 시작값은 1/10/20을 쓴다(실제 시작값과 같지만 개인정보가 아님).
  4. **한글 금액·순번 묶음**: `korean_amount`, `category_groups`, `format_item_note` 결과.
  5. **가격표 해석**
     - 합성 시험 엑셀 2개를 만든다. 이 엑셀은 저장소에 넣는다. 출입통제 형식(설치·철거·이전설치·배관배선·일반 품목, 같은 모델 2행)과 제품 형식(21행 시작, 여러 시트, 모델명 패턴 2종, 수식 단가, B열 이어받기, 사진 1장·자르기)을 갖춘다.
     - 합성 엑셀에 대한 `access_catalog.read`, `catalog.parse` 결과는 `tests/golden/`에 둔다.
     - 실제 `private/prices/*.xlsx` 결과는 `private/golden/`에 둔다.
     - 사진은 품목별 개수와 템플릿의 표시 크기(`imageSizes` 값)만 남긴다. 새 코드는 축소 방식이 달라 사진 id가 기존과 다르다. 이는 의도된 차이이므로 id는 비교하지 않는다.
  6. **PDF 비교용 원본**: 합성 입력 몇 개(5종 각각, ④⑤는 1·4·5·9품목)로 기존 `pdf_quote.write_pdf`가 만든 PDF를 `private/compare/legacy/`에 둔다.
     - 글꼴은 `private/fonts`의 맑은 고딕과 KoPub를 기존 파일명으로 바꾼 복사본 폴더를 `NROBOTICS_FONT_DIR`로 지정한다.
     - `private/reference/` 5종의 입력을 xlsx에서 복원할 수 있으면 그것도 같은 방식으로 만든다.
- 재실행해도 같은 결과가 나와야 한다(결정적).

**검증**: 스크립트를 실행해 산출 파일들이 생기는지 확인한다. `git ls-files`로 `private/` 산출물이 추적되지 않는지 확인한다. 생성 명령은 README 개발 절에 적는다.

**생각의 근거**: 사용자는 '기존 코드와 자동 비교'를 골랐고 Python 설치를 승인했다. 정답을 한 번 만들어 저장소에 넣으면 이후 검사에 Python이 필요 없다.

## T2 — 도메인 모듈 (계산·검증·한글 금액·순번 묶음·파일명)

**목표**: 화면과 서버가 함께 쓰는 순수 TypeScript 도메인. spec 7·8절과 12절의 표기 규칙이 대상이다.

**작업 대상**: `src/domain/`(`types.ts`, `money.ts`, `calculate.ts`, `validate.ts`, `format.ts`), `tests/domain/`

**동작 계약**
- 금액은 정수(BigInt 또는 정수 스케일 10진)로만 계산한다. 반올림은 ROUND_HALF_UP이다.
  - 수량은 소수 3자리, 적용률은 2자리로 받는다. 기존 화면의 정수 스케일 계산과 같은 결과를 내야 한다.
- `lineAmount`, `calculate(items, type) → {subtotal, tax, total}`, `catalogTotals`(할인·수수료), 자동 노무비·경비 함수.
- `validateQuote(raw) → 정규화된 견적 | 오류(한국어 메시지)`: spec 8절 규칙과 문구 그대로다.
  - 가격표 연동 덮어쓰기는 T8 몫이다. 이 함수는 가격표 데이터를 인자로 받을 수 있게만 열어 둔다.
- `koreanAmount`, `categoryGroups`(묶음 순번), `categorySpans`, `formatItemNote`, `safeCustomerName`.
- 프레임워크와 Node 전용 API에 의존하지 않는다. 브라우저와 서버 모두에서 돌아야 한다.
- `types.ts`에 견적 입력, 품목, 견적 종류, 가격표 항목(출입통제·제품·템플릿), 담당자 타입을 정의한다. 다른 작업이 이 타입을 쓴다.

**검증**: `tests/golden/`의 계산·검증·한글 금액·순번 정답과 전부 일치한다. 경계 사례가 대상이다: 50,000,000 경계, .5 반올림, 0원, 최대값, 9,999,999,999,999 초과 오류.

## T3 — 견적번호 경계 (브라우저 구현)

**목표**: spec 9절. 나중에 DB로 바꿀 수 있는 번호 발급 경계와, 브라우저 저장소 구현.

**작업 대상**: `src/numbering/`(경계 정의, 순수 계산, 브라우저 저장소 구현), `tests/numbering/`

**동작 계약**
- 순수 함수: `nextSerial(history, date, staffStart)`, `formatNumber`, `checkManual(history, number)`.
  - 규칙: max(시작값, 그 담당자 그날 최대+1). 그날 쓰인 번호와 직접 입력 번호에서 파생된 번호는 건너뛴다. 999를 넘으면 오류다.
- 경계 인터페이스: `previewNext(date, staffId)`, `checkManual(number)`, `record(entry)`.
  - 비동기로 정의해 서버 구현으로 바꿔 끼울 수 있게 한다.
- 브라우저 구현은 저장소 키 하나에 이력을 둔다. 저장소를 쓸 수 없으면 빈 이력으로 동작하고 오류를 알린다.
- `record`는 생성 성공 후에만 호출된다. 호출 순서 보장은 T9 몫이지만, 이 모듈의 문서 주석에 명시한다.

**검증**: `tests/golden/`의 번호 시나리오 정답과 일치한다.

## T4 — 가격표 변환 (빌드 전 단계)

**목표**: spec 10·11절의 해석 규칙. `private/prices/*.xlsx`를 화면과 서버가 쓰는 데이터와 사진으로 변환한다.

**작업 대상**: `scripts/prepare-data.ts`(`npm run prepare-data`), `src/pricelists/`(해석기: 출입통제·제품·서식 읽기), 변환 산출 폴더(gitignored), `tests/pricelists/`, `tests/fixtures/`(T1이 만든 합성 엑셀)

**동작 계약**
- 해석은 ZIP·XML을 직접 읽어 기존 Python 규칙을 그대로 옮긴다.
  - 대상: 머리글 탐지, 21행 시작, 합계 행, 모델명 추출, id 해시, 수식 단가 경고, 테마 색·tint, 열 너비·행 높이, 사진 앵커·자르기·크기.
- 사진은 sharp로 줄인다. 기본값은 긴 변 600px, JPEG 품질 85이고, 투명하면 PNG다(조정 가능).
- 산출물
  - 출입통제 항목 목록과 revision.
  - 제품 항목 목록(사진 제외 데이터, 템플릿, 조건 문구, 경고, 시트 목록)과 revision.
  - 사진 파일들(id → 파일).
- `private/prices/` 파일이 없거나 해석이 실패하면 무엇이 문제인지 한국어로 알리고 0이 아닌 코드로 끝낸다.
- 압축 해제 크기 제한은 출입통제 50MB다.

**검증**
- 합성 엑셀 해석 결과가 `tests/golden/` 정답과 일치한다.
  - 사진은 품목별 개수와 표시 크기로 비교하고, 사진 id는 비교하지 않는다.
  - 템플릿 색은 짝수 반올림 규칙으로 계산한 값이 정답과 같아야 한다.
- `private/`에 실제 파일이 있으면 `private/golden/`과 항목·id·단가·경고·조건·사진 개수를 비교하는 검사가 추가로 돌고 통과한다. 파일이 없으면 이 검사는 건너뛴다.

## T5 — PDF 생성기

**목표**: spec 12절. 기존 `pdf_quote.py`와 거의 같은 PDF.

**작업 대상**: `src/output/pdf/`, `src/output/fonts.ts`(글꼴 지정 한곳), `tests/output/pdf/`

**동작 계약**
- 입력은 검증된 견적(T2 타입)과 가격표 사진 조회 함수, 출력은 PDF 바이트다.
- 기존 배치 규칙을 그대로 옮긴다. 대상은 다음과 같다.
  - 열 너비 비율(①② base_layout, ③ 고정, ④⑤ 템플릿)과 글꼴 크기 환산.
  - 상단 표, 공급자 표, 로고 위치, 특기사항·금액 표(④⑤ 수수료 칸), 품목 표.
  - 묶음 병합, 빈 행, 합계 표, NOTE.
  - 비고 글꼴 단계 축소(7.4→7→6.6→6.2), 행 높이 측정.
  - ④⑤ 템플릿 줄 서식과 사진 크기, 페이지 4품목 분할, 2쪽 이후 상단 생략, 전체 동일 축소, 쪽 번호.
- 글꼴: ①②③은 맑은 고딕 보통·굵게(`private/fonts`), ④⑤는 KoPub Medium(저장소).
  - 글꼴 경로와 이름은 `fonts.ts` 한곳에만 둔다.
  - 맑은 고딕 파일이 없으면 "맑은 고딕 글꼴 파일(private/fonts)이 없습니다" 오류를 낸다.
- 표 안 줄바꿈은 한글 글자 단위 줄바꿈을 지원해야 한다. 기존의 CJK 줄바꿈과 같은 동작이다.

**검증**
- 자동: 5종 × 여러 품목 수에서 페이지 수(①②③=1, ④⑤=⌈n/4⌉)를 확인한다.
- 자동: 추출 텍스트에 줄 합계·합계·견적가 문자열("₩…" / "…원")과 "일금…원정"이 들어 있는지 확인한다.
- 자동: ④⑤ 수수료 칸 ON/OFF를 확인한다.
- 자동: 100품목·사진 많은 ④⑤ PDF가 4.5MB 미만인지 확인한다.
- 모양의 사람 확인은 T10에서 한다.

## T6 — Excel 생성기

**목표**: spec 13절. 기존 `xlsx_quote.py`와 거의 같은 편집 가능한 xlsx.

**작업 대상**: `src/output/xlsx/`, `tests/output/xlsx/`

**동작 계약**
- 입력과 출력은 T5와 같은 형태이고, 결과는 xlsx 바이트다.
- 기존과 같은 좌표 격자로 셀을 배치한다. 셀 병합, 테두리, 채움색, 글꼴 이름·크기·굵기·색, 정렬, 줄바꿈을 재현한다.
- 살아 있는 수식과 계산값을 함께 기록한다. 수식은 줄 합계 ROUND, 합계 SUM, 부가세 ROUND×0.1, ④⑤ 5천만 원 IF 할인, 상단 '일금' TEXT 수식이다.
- 수량 형식 `#,##0.###`, 금액 `#,##0`.
- 시트 분할은 ④⑤가 4품목마다다. A4 세로, 한 장 맞춤, 눈금선 숨김, 확대 85%.
- 사진 위치는 비고 칸이다.
- `= + @`로 시작하는 입력은 문자로 넣는다.

**검증**
- 자동: 시트 수를 확인한다.
- 자동: 수식 문자열이 기존 규칙과 같은지 확인한다.
- 자동: 기록된 계산값이 T2 계산과 같은지 확인한다.
- 자동: 사용자 입력 '=1+1'이 문자로 들어가는지 확인한다.
- 자동: ④⑤ 할인 경계에서 수식 결과와 계산값이 일치하는지 확인한다.

## T7 — 입장 비밀번호와 담당자 설정

**목표**: spec 5·6절.

**작업 대상**: 미들웨어(모든 요청 검사), `src/auth/`(쿠키 서명·검증), 입장 페이지와 입장·나가기 API, `src/staff/`(STAFF_CONFIG 읽기·검증), `tests/auth/`, `tests/staff/`

**동작 계약**
- 쿠키 서명에 `APP_PASSWORD`를 넣어, 비밀번호를 바꾸면 기존 쿠키가 무효가 되게 한다.
  - 비교는 시간 일정 비교로 한다.
  - 쿠키는 HttpOnly, SameSite=Lax, 배포 시 Secure, 30일(조정 가능)이다.
- 보호 제외는 입장 페이지와 그 정적 자원, 입장 API뿐이다.
  - 그 밖의 페이지는 입장 페이지로 보낸다. API는 401 `{error:"입장이 필요합니다. 화면을 새로고침해 주세요."}`를 돌려준다.
- `APP_PASSWORD`가 없거나 비었으면 입장 API가 항상 거부한다. 화면에는 "관리자가 비밀번호를 설정하지 않았습니다"를 표시한다.
- 틀린 비밀번호는 약 1초 지연 후 거부한다(조정 가능).
- 담당자: `STAFF_CONFIG` JSON을 spec 6절 규칙으로 검증한다. 표시 이름을 만들고 시작값을 노출한다. 형식 오류면 명확한 오류를 낸다.

**검증**
- 자동: 미입장 상태의 페이지·API 차단, 틀린 비밀번호, 맞는 비밀번호, 비밀번호 변경 후 쿠키 무효, 미설정 시 전원 차단을 확인한다.
- 자동: STAFF_CONFIG 정상·오류 사례를 확인한다.

## T8 — 서버 API

**목표**: spec 11절 서버 검증과 14절 생성. 가격표·담당자 조회.

**작업 대상**: `src/app/api/` 아래 경로 처리기, `tests/api/`

**동작 계약** (모두 입장 필요. 오류는 `{error: 한국어}`)

| 경로 | 입력 | 출력 | 오류 |
|---|---|---|---|
| `GET /api/access-catalog` | — | `{entries:[{id,title,model,category,name,unit,qty,price,note,costBucket}], revision}` | 500 변환 데이터 없음 |
| `GET /api/catalog` | — | `{entries:[{id,sheet,model,code,title,category,name,unit,qty,price,note,internalNote,imageIds,terms,template}], sheets, warnings, revision}` | 500 |
| `GET /api/catalog-image/{id}` | 사진 id | 이미지(JPEG/PNG) | 404 "제품 사진이 없습니다." |
| `GET /api/staff` | — | `{staff:[{id,name,title,display,phone,start}]}` | 500 설정 오류 |
| `POST /api/generate` | spec 8절 요청 본문 표의 JSON, 크기 300KB 이하 | 파일 바이트, `Content-Disposition: attachment; filename*=UTF-8''견적서_{거래처}.{확장자}` | 400 검증 오류 메시지, 413 "입력내용이 너무 큽니다." |

- generate 처리 순서
  1. T2로 검증한다.
  2. ④⑤면 가격표 revision을 확인하고, 연동 줄을 덮어쓰고, 사라진 연동 제품이면 거부한다. 연동 안 된 줄의 사진 id는 거른다.
  3. 받은 번호를 그대로 쓴다. 번호 발급은 브라우저 몫이다.
  4. T5·T6로 생성해 응답한다. 파일을 저장하지 않는다.
- 생성 결과를 검사한다: PDF는 `%PDF-`로 시작하는지, xlsx는 ZIP 무결성과 workbook 존재 여부다. 실패하면 500 "견적서 생성 확인에 실패했습니다."를 돌려준다.
- 함수 실행 시간 설정은 Hobby 한도 안에서 둔다(조정 가능).
- 변환 산출물·글꼴·로고가 서버 함수 번들에 포함되도록 설정한다.

**검증**: 입장 쿠키를 붙인 요청으로 각 경로의 정상·오류를 확인한다(합성 가격표 산출물 사용). 대상은 revision 불일치, 사라진 연동 제품, 300KB 초과, 형식별 응답 헤더와 파일 시작 바이트다.
