# 배포 가이드

이 문서는 저장소를 처음 받은 사람이 처음부터 끝까지 따라 하면 Vercel에 배포할 수 있도록 쓴 절차입니다.
명령은 저장소 폴더(`package.json`이 있는 폴더)에서 실행합니다.

> 이 앱은 GitHub 연결 자동 배포를 쓰지 않습니다. 회사 가격표·글꼴이 저장소에 없기 때문입니다.
> **자료가 있는 PC에서 직접 빌드한 결과물을 올립니다**(`vercel build` → `vercel deploy --prebuilt`).

## 1. 준비물

| 준비물 | 확인 방법 |
|---|---|
| Node.js 22 이상 | `node -v` |
| Vercel 계정 | https://vercel.com 가입 |
| Vercel CLI | `npm install -g vercel` 후 `vercel --version` |
| 이 저장소 | `git clone https://github.com/YongWookLEE/nrobot.git` (비공개 저장소라 접근 권한 필요) |
| 비공개 자료 | 아래 2절 |

의존성을 설치합니다.

```bash
npm install
```

## 2. 비공개 자료 준비

저장소에는 회사 자료가 없습니다. 아래 파일을 받아 **정확히 이 이름으로** `private/` 폴더에 둡니다. `private/`는 git에 올라가지 않습니다.

| 넣을 위치 | 원본 파일 | 받는 곳 |
|---|---|---|
| `private/prices/access.xlsx` | `260730_출입통제 기준가격_06.xlsx` | 회사 담당자 (출입통제 기준가격표) |
| `private/prices/catalog.xlsx` | `(주)앤로보틱스_ 2026년도 견적서 양식.xlsx` | 회사 담당자 (영업팀 제품가격표) |
| `private/fonts/malgun.ttf` | 맑은 고딕 보통 | Windows PC의 `C:\Windows\Fonts\malgun.ttf` |
| `private/fonts/malgunbd.ttf` | 맑은 고딕 굵게 | Windows PC의 `C:\Windows\Fonts\malgunbd.ttf` |

- 맑은 고딕은 ①②③ 견적서 PDF에 들어갑니다. 파일이 없으면 ①②③ PDF를 만들 때 "맑은 고딕 글꼴 파일(private/fonts)이 없습니다" 오류가 납니다.
- 다른 글꼴 파일을 맑은 고딕 이름으로 바꿔 넣지 마세요. 오류 없이 만들어지지만 PDF 모양이 달라집니다.

자료가 제대로 읽히는지 확인합니다.

```bash
npm run prepare-data
```

`가격표 변환 완료: 출입통제 N개, 제품 N개, 사진 N개` 문구가 나오면 성공입니다.

## 3. 환경 변수

| 이름 | 내용 | 예시 (가짜 값) |
|---|---|---|
| `APP_PASSWORD` | 입장 비밀번호. 비어 있으면 **아무도 들어갈 수 없습니다.** 쿠키 서명에도 쓰이므로 16자 이상의 무작위 문자열을 권합니다. | `change-me-to-a-long-random-text` |
| `STAFF_CONFIG` | 담당자 명단 JSON 배열. **한 줄로** 적습니다. | 아래 참고 |

```json
[{"id":"a","name":"홍길동","title":"차장","phone":"010-0000-0001","start":1},{"id":"b","name":"김철수","title":"대리","phone":"010-0000-0002","start":10}]
```

- `id`: 겹치지 않는 영문 식별자. 한번 정하면 바꾸지 마세요(브라우저의 번호 이력·휴대폰 기억이 id 기준입니다).
- `name` 1~30자, `title` 20자 이하(비워도 됨), `phone` 30자 이하.
- `start`: 그 담당자가 하루에 처음 받는 견적번호(1~999). 예: 10이면 `NSFF0-날짜-010`부터 시작합니다.
- 형식이 틀리면 화면에 "담당자 설정(STAFF_CONFIG)을 확인하세요"가 나옵니다.

### 로컬 실행용

```bash
cp .env.example .env
```

`.env`를 열어 실제 값으로 바꿉니다. `.env`는 git에 올라가지 않습니다.

### Vercel 설정

둘 중 편한 방법으로 넣습니다. 환경(Environment)은 **Production**을 고릅니다.

- **화면**: Vercel 대시보드 → 프로젝트 → Settings → Environment Variables → 이름·값 입력 → Save.
- **명령**: 실행하면 값을 물어봅니다. `STAFF_CONFIG`는 한 줄 JSON을 그대로 붙여 넣습니다.

  ```bash
  vercel env add APP_PASSWORD production
  vercel env add STAFF_CONFIG production
  ```

환경 변수를 바꾼 뒤에는 **다시 배포해야** 반영됩니다(5절).

## 4. 처음 배포

```bash
vercel login                       # 처음 한 번. 브라우저에서 로그인
vercel link                        # 처음 한 번. 프로젝트를 새로 만들거나 기존 프로젝트를 고름
vercel pull --yes --environment=production
npm run build:vercel               # = vercel build --prod + 결과물 검사 (아래 주의 참고)
vercel deploy --prebuilt --prod
```

> **`vercel build --prod`를 직접 실행하지 말고 `npm run build:vercel`을 쓰세요.**
> Vercel의 Next.js 빌드 도구는 프로젝트 폴더 맨 위의 `.env`·`.env.local` 같은 파일을 서버 함수에 그대로 넣습니다.
> 이 PC에서 빌드해 올리면 실제 비밀번호·담당자 정보가 파일째 올라갑니다.
> `npm run build:vercel`은 빌드하는 동안만 이 파일들을 `.vercel/env-hold/`로 옮겼다가 되돌리고,
> 결과물에 환경 변수 파일·가격표 원본·비공개 자료가 없는지 검사합니다. 검사가 실패하면 올리지 마세요.
> 중간에 강제로 멈춰 `.vercel/env-hold/`에 파일이 남으면 프로젝트 폴더로 되돌려 놓으세요.

- `vercel link`: "Link to existing project?"에서 처음이면 `N`을 고르고 프로젝트 이름(예: `nrobot`)을 정합니다. 설정은 `.vercel/` 폴더에 저장되며 git에 올라가지 않습니다.
- `vercel link`는 프로젝트 폴더에 `.env.local`(Vercel 접속용 토큰)을 만들 수 있습니다. git과 빌드 결과물에서 모두 제외되므로 그대로 두어도 됩니다.
- 저장소의 `vercel.json`이 프레임워크를 Next.js로 지정합니다. 이 파일이 없으면 "No Output Directory named "public"" 오류로 빌드가 실패할 수 있습니다.
- `npm run build:vercel`: 이 PC에서 가격표 변환(`prepare-data`)과 앱 빌드를 합니다. 결과물은 `.vercel/output/`에 생기고 `private/`의 변환 자료와 글꼴이 함께 들어갑니다. 원본 엑셀은 들어가지 않습니다.
- `vercel deploy --prebuilt --prod`: 빌드 결과물만 올립니다. 끝나면 배포 주소가 나옵니다.
- Vercel 프로젝트 Settings → General → Node.js Version은 22.x 이상을 고릅니다.

배포 후 확인합니다.
1. 배포 주소를 열면 비밀번호 화면이 나와야 합니다.
2. 비밀번호를 넣으면 처음 화면(랜딩페이지)이 나오고, '견적서 작성'으로 입력 화면에 들어갈 수 있어야 합니다.
3. 품목 하나를 넣고 PDF와 Excel을 하나씩 만들어 내려받아 봅니다.

## 5. 자주 하는 일

모두 **다시 배포**로 반영합니다. 다시 배포는 아래 두 줄입니다(로그인·연결은 다시 하지 않아도 됩니다).

```bash
npm run build:vercel
vercel deploy --prebuilt --prod
```

| 할 일 | 방법 |
|---|---|
| 가격표 교체 | 새 엑셀을 `private/prices/access.xlsx` 또는 `catalog.xlsx`로 **같은 이름으로** 덮어쓰고 `npm run prepare-data`로 확인한 뒤 다시 배포 |
| 비밀번호 변경 | Vercel 환경 변수 `APP_PASSWORD`를 바꾸고 `vercel pull --yes --environment=production` 후 다시 배포. **모든 사용자가 다시 입장해야 합니다.** |
| 담당자 변경 | `STAFF_CONFIG`를 바꾸고 `vercel pull` 후 다시 배포. 기존 담당자의 `id`는 유지합니다. |

- 제품가격표가 바뀌면, 사용자가 이미 넣어 둔 연동 품목은 화면을 열 때 새 값으로 바뀌고 바뀐 줄을 알려 줍니다.
- 가격표에서 제품을 지우거나 이름을 바꾸면 그 제품을 쓴 입력 초안은 "다시 선택하세요" 표시가 나오고 생성이 거부됩니다.

## 6. 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| `npm run build:vercel` 뒤에 `npm run build`가 "An unexpected Turbopack error"로 실패 | Vercel 빌드가 남긴 `.next` 캐시와 충돌한 것입니다. `.next` 폴더를 지우고 다시 실행합니다(macOS·Linux `rm -rf .next`, Windows `rmdir /s /q .next`). 업로드 전이라면 `npm run build:vercel`을 다시 실행한 뒤 올립니다. |
| `npm run build:vercel`이 "빌드 결과물에 배포하면 안 되는 파일이 있습니다"로 끝남 | 목록에 나온 파일이 결과물에 들어갔습니다. 올리지 말고, 해당 파일을 프로젝트 폴더 맨 위에서 치우거나 `next.config.ts`의 제외 설정을 확인한 뒤 다시 빌드합니다. |
| 빌드가 `private/prices/access.xlsx 파일이 없습니다`로 실패 | 2절의 파일 이름·위치를 확인합니다. 파일 이름이 정확히 `access.xlsx`, `catalog.xlsx`여야 합니다. |
| 빌드가 `...단가를 확인하세요`로 실패 | 출입통제 가격표의 단가 칸에 숫자가 아닌 값이 있습니다. 엑셀에서 해당 시트·행을 고칩니다. |
| 화면에 "관리자가 비밀번호를 설정하지 않았습니다" | `APP_PASSWORD`가 비어 있습니다. 3절대로 넣고 다시 배포합니다. |
| 맞는 비밀번호인데 입장이 안 됨 | 환경 변수를 바꾼 뒤 다시 배포하지 않았거나, 값 앞뒤에 공백이 들어갔는지 확인합니다. |
| 로컬에서 `npm run start`로 띄웠는데 입장이 안 됨 | 운영 모드는 https 전용 쿠키를 씁니다. 주소를 `http://localhost:3000`으로 열어야 쿠키가 저장됩니다. |
| "담당자 설정(STAFF_CONFIG)을 확인하세요" | JSON이 한 줄인지, 따옴표·쉼표가 맞는지, `id`가 겹치지 않는지 확인합니다. |
| ①②③ PDF 생성 시 "맑은 고딕 글꼴 파일(private/fonts)이 없습니다" | 2절의 글꼴 파일을 넣고 다시 빌드·배포합니다. |
| "제품 엑셀이 변경되었습니다. 최신 내용을 불러온 후 다시 만들어주세요." | 사용 중에 새 가격표가 배포되었습니다. 화면을 새로고침한 뒤 다시 만듭니다. |
| 생성이 실패하고 "입력내용은 유지되어 있습니다." | 메시지 앞부분의 이유(빈 칸, 잘못된 숫자 등)를 고친 뒤 다시 만듭니다. 실패한 생성은 견적번호를 쓰지 않습니다. |

## 7. 주의

- **무료(Hobby) 요금제는 개인·비상업 용도 조건이 있습니다.** 회사가 정식으로 쓰면 유료(Pro) 전환을 검토하세요.
- **맑은 고딕 글꼴을 서버에 올려 PDF에 넣는 것은 라이선스상 문제가 될 수 있습니다.** 정식 운영 전에 회사가 판단해야 합니다. 글꼴 지정은 `src/output/fonts.ts` 한곳에 있어, 파일만 바꾸면 다른 글꼴로 바꿀 수 있습니다.
- **견적번호는 브라우저별로 발급합니다.** 다른 PC·브라우저끼리는 번호가 겹칠 수 있습니다.
- **개인정보와 회사 자료는 저장소에 올리지 않습니다.** 커밋 전에 `git status`로 `private/`, `.env`, `.vercel/`이 없는지 확인하세요. `npm test`의 저장소 경계 검사도 이를 확인합니다.
